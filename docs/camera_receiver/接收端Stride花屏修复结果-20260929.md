# 接收端 Stride 花屏修复结果

日期：2026-09-29
目标程序：`bin/peerconnection_camera_stridefix`
SHA256：`1c26c76cafe55a007cff285ea5346b956d73382a272dc7e1c3c1c54ced52c4ef`

## 1. 根因确认

花屏根因已经从诊断阶段进一步确认：

1. 实际解码帧尺寸为 `960x540`；
2. Y/U/V 的实际行跨度为：

```text
strideY=1024
strideU=512
strideV=512
```

3. 原导出代码使用：

```cpp
memcpy(..., DataY(), width * height);
```

它把 `1024` 字节行距中的对齐填充当成有效像素连续复制，导致播放器按 `960` 紧凑行距解释时出现横条、绿带和斜向错位。

同时发现第二个旧导出位置：

```text
video/video_receive_stream2.cc
```

它写入硬编码目录：

```text
/app/media/res_video/
```

此前同样使用整块 `memcpy`。该目录不存在时会输出 `Failed to open the dumping file`，但不是当前 `--dump_path` 文件花屏的来源。

## 2. 已实施修复

### 2.1 `cricket::VideoRenderer::OnFrame`

已修改：

```text
examples/peerconnection_headless/client/conductor.h
```

修复内容：

- 使用 `ToI420()` 获取明确的 I420 buffer；
- 首次或布局变化时输出真实宽高和 StrideY/U/V；
- Y/U/V 三个平面逐行复制；
- 每行只复制有效宽度，不复制 stride 中的对齐填充；
- 移除 `new[]` 临时缓冲区，避免内存泄漏；
- 先写 `received_*.yuv.tmp`，成功后原子重命名为 `received_*.yuv`；
- 输出失败时删除临时文件并打印实际路径。

### 2.2 `VideoReceiveStream2`

已修改：

```text
video/video_receive_stream2.cc
```

修复内容：

- 旧 `/app/media/res_video` 导出路径也改成逐行 stride-safe 写入；
- 使用临时文件和原子重命名；
- 只有 `/app/media/res_video` 存在且可写时才启用旧导出；
- 相机外部录制使用 `--dump_path` 时，不再反复输出无用的 `Failed to open the dumping file`。

修改源码 diff：

```text
docs/camera_receiver/stridefix-source-changes.patch
```

## 5. 对方部署命令

下载仓库中的：

```text
bin/peerconnection_camera_stridefix
bin/peerconnection_camera_stridefix.sha256
```

放到 Receiver 的 WSL：

```text
$HOME/pandia-camera-test/bin/peerconnection_camera_stridefix
```

验证：

```bash
cd "$HOME/pandia-camera-test/bin"
sha25sum -c peerconnection_camera_stridefix.sha256
```

启动 Receiver：

```bash
run_dir="$(mktemp -d "$HOME/pandia-stridefix-XXXXXXXX")"
mkdir -p "$run_dir/frames"

docker run -d \
  --name pandia-stridefix-rx \
  --network host \
  --gpus all \
  -e NVIDIA_DRIVER_CAPABILITIES=all \
  --mount type=bind,src="$HOME/pandia-camera-test/bin",dst=/opt/pandia-bin,readonly \
  --mount type=bind,src="$run_dir/frames",dst=/dump \
  -e LD_LIBRARY_PATH=/opt/nvidia-libs \
  --entrypoint /opt/pandia-bin/peerconnection_camera_stridefix \
  johnson163/pandia_receiver:latest \
  --receiving_only \
  --port 9999 \
  --dump_path /dump
```

注意：如果 `nvidia-libs` 不是放在同一目录，请相应调整挂载路径。

Sender 可以继续使用原来的：

```text
bin/peerconnection_camera
```

也可以统一使用 `peerconnection_camera_stridefix`。两者信令兼容，但 Receiver 必须使用 stridefix 版本才能保证 YUV 导出不花屏。
